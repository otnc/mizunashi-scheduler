# @mizunashi/parser

函館市が公開する入浴可能時間表を読むパーサです。非公開パッケージ。

**このデータソースはフォーマットが毎年変わります。** 12 年分を調査した結果、命名規則・ファイル形式・時刻表現・対象期間・列の意味がすべて変動していました。そのため「今のフォーマットを読む 1 本のパーサ」ではなく、**まだ見ていない変化をコード改変なしに吸収できる**構造にしてあります。

## 構成

```
sniff        容器の判定（zip か、テキストか）
readers/     容器 → Table（xlsx / csv）
locate/      Table → 構造（ヘッダ探索・形状推論・行ブロック高）
recognize/   値の認識器（時刻 / 日付 / 曜日）
extract      構造 + Table → RawEntry
normalize/   年の解決・セッションの組み立て
split        暦年バケットへの分割
```

**容器（Reader）と構造（locate）が直交しています。** これ以降の処理は元が xlsx だったか csv だったかを知りません。実際、CSV 対応で `locate` 以降には一切手を入れていません。

## 使い方

```ts
import { parseDocument, splitByCalendarYear } from '@mizunashi/parser';

const parsed = parseDocument({ bytes, fileName, contentType, linkLabel });
const buckets = splitByCalendarYear(parsed.days);
```

## 設計上の要点

**列位置を決め打ちません。** ヘッダ行の語句から列の役割を決めます。ヘッダが見つからない場合は、値の形（時刻らしい値の割合）から構造を推論します。

**行ブロック高を推論します。** xlsx は「1 日 = 2 行」、CSV は「1 日 = 1 行」ですが、これも決め打たず、時刻列に値が入る行の間隔から求めます。

**単一の情報源を信用しません。** 月日は日付テキストと Excel シリアル値の 2 系統から取り、**原本の曜日列との一致率が高い方を選びます**。実際に必要でした。

- 2021 / 2022 年版はシリアル値の年が 2020 年のまま放置されている
- 2021 年版の 3 月シートは英語日付が全 31 行とも `MAR.3`

どちらも単独では信用できず、曜日との突き合わせで初めて正しい年月日に収束します。

**表記ゆれはコードではなくデータで持ちます。** `vocabulary.ts` の配列に 1 要素足すだけで新しい表記に対応できます。

**壊れたセルで全体を落としません。** 単発の異常は `Diagnostics` に計上して該当分だけ捨て、件数が閾値を超えたときだけ取り込みを却下します。実データには孤立した区切り記号 400 箇所、時刻の誤入力（`19;00`）、長さ 0 のセッションが実在します。

## テスト

実データ 6 件（2016 / 2017 の CSV、2020 / 2021 / 2022 / 2026 の XLSX）に対するゴールデンテストがあります。日数・セッション数分布・祝日件数・警告件数まで既知の値と突き合わせます。

**フィクスチャの実データはリポジトリに含まれていません**（函館市の原本そのもので再配布にあたるため）。取得元は [`packages/core/test/fixtures/README.md`](../core/test/fixtures/README.md) にあります。無い環境ではゴールデンテストはスキップされます。

## 対応する容器

| 形式 | 対応 |
| --- | --- |
| XLSX | ○ |
| CSV | ○（Shift_JIS / UTF-8 自動判別） |
| XLS（旧 BIFF） | × 2019 年に 1 度だけ使われた。Reader を追加すれば対応可能 |
| PDF | × 表抽出の誤読が入浴可否の誤判定に直結するため意図的に非対応 |
